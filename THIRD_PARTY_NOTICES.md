## FFmpegInteropX

All Bale builds bundle modified [FFmpegInteropX.UWP.Lib](https://github.com/Zorro92/bale-ffmpeginteropx)
**2.1.0-bale.84**, a Bale x64 native-wrapper fork of upstream 2.1.0, under **Apache-2.0**.
Its full license text is packaged as `Licenses/FFmpegInteropX.txt`
(source copy: `src/Bale.Xbox/Assets/FFmpegInteropX-LICENSE.txt`). Corresponding source is at
[Zorro92/bale-ffmpeginteropx](https://github.com/Zorro92/bale-ffmpeginteropx), pinned to commit
`9e34046460c0e8595292d5dc6725b8c7e3412850`. The former 22-patch Bale series is preserved there
as commits, including upstream PR #482's colour-attribute fix, decode-ahead tuning, GPU grain and
zero-copy AV1 delivery, system Dolby decoding and bitmap subtitle delivery to Bale's overlay.
The fork also fixes HDR metadata and display-matrix reads to use the side-data payload.
Version bale.25 adds the opt-in PQ P010 → SDR NV12 tone-map stage, using Bale tone-map ABI 1;
it is disabled unless the debug-only bale_tonemap key is set. Version bale.84 adds an opt-in in-band caption packet tap (`bale_cc_sink`), which hands each video packet to Bale's caption decoder in bale_gpu. Version bale.83 creates the D3D12 probe's own device at feature level 11_0. Version bale.82 builds on FFmpeg 9.1 (native 9.1.0-bale.dav1d.1.5.5; the zero-copy AV1 key is gone with patch p1), takes upstream's teardown crash fixes (#488, #489) and adds an opt-in D3D12 video decode support probe (bale_d3d12va_probe, logging only). Version bale.81 converts software frames that are not 8-bit 4:2:0 with swscale's slice threads (up to four). Version bale.80 runs the processing stage (tone map, downscale to the output size, dithered output) on software-decoded frames too, through a staged D3D11 upload. Version bale.79 sizes stream-based decoder pools from in-band parameter sets when the codec configuration has none. Version bale.78 takes rav1g interface version 3 (display peak from HDR metadata, cubic chroma). Version bale.77 adds bale_tonemap_white_nits (SDR white for the stage and rav1g's display pass). Version bale.76 retires the direct decoder-frame read (bale_d3d11va_shader_resource is ignored). Version bale.75 uses the stage when the device can't make shader-writable display-size images. Version bale.74 takes rav1g interface version 2 and its optional display output (debug trial, bale_rav1g_display). Version bale.73 adds rav1g's per-frame record line (with rav1g 0.6.0-alpha.3 or later). Version bale.72 adds a per-frame rav1g stage timing line (debug bale_rav1g_perf=2). Version bale.71 caps stream-sized pools at FFmpeg's real pool (fixes VP9) and logs every pool decision. Version bale.70 adds the rav1g image-pool breakdown and bale_gpu_output_images (cap 0-16). Version bale.69 extends that pool sizing to H.264 and VP9. Version bale.68 adds the opt-in bale_d3d11va_pool_from_stream (HEVC decoder pool sized from the stream). Version bale.67 picks rav1g output images whose release fence has passed (logs image release waits). Version bale.66 adds rav1g delivery diagnostics (decode call, read, gap and wait timings). Version bale.65 refreshes the rav1g headers to v0.6.0-alpha.1 (perf record 624 bytes). Version bale.64 makes those pools shader-readable only when bale_gpu advertises BALE_TONEMAP_INPUT_DECODER_SRV (64). Version bale.63 adds the opt-in bale_d3d11va_shader_resource experiment (shader-readable d3d11va decoder pools). Version bale.62 reports GPU memory to the bale_gpu memory ledger (categories 16–22). Version bale.61 adds bale_tonemap_output_depth (8 = dithered NV12 stage output). Version bale.60 adds D3D11 GPU film grain for dav1d without zero-copy (bale_film_grain_mode=3). Version bale.59 adds bale_av1_fallback_max_height (refuse a rav1g-declined open above that height instead of falling back to dav1d). Version bale.58 reads rav1g v0.5.0-alpha.1's larger timing record (bale_rav1g_perf). Version bale.57 lets the rav1g route create up to 10 output images per stream (on demand). Version bale.56 can cap the player-side textures of the rav1g route. Version bale.55 logs a per-stream rav1g memory breakdown. Version bale.54 fixes a rav1g seek livelock and keeps 4 units in flight by default. Version bale.52 feeds rav1g from its own thread (units in flight), keeps the position on resume after a cancel, and adds optional rav1g timing. Version bale.50 logs rav1g delivery in sample time with the delivered rate. Version bale.49 adds rav1g delivery diagnostics to the log. Version bale.48 fixes a rav1g frame-pool deadlock, adds a prewarm export for the rav1g device and limits the player-side pool by available memory. Version bale.45 fixes a crash when the rav1g provider opens. Version bale.44 adds an opt-in GPU AV1 provider for rav1g (bale_av1_decoder=1, which Bale sets in every build since 2026-11-26 where rav1g.dll is usable; unset changes nothing). Version bale.43 removes the debug-only tone-map output variants (bale_tonemap_output, bale_tonemap_format; still accepted and ignored). Version bale.42 keeps the source depth in FFmpeg software output: more than 8 bits outputs P010, 8-bit sources (also 4:2:2, 4:4:4, full range, RGB, grey) output NV12. Version bale.41 makes FFmpeg software decode output P010 (10-bit) for every source swscale converts (more than 8 bits, not 4:2:0, full range, RGB, grey); plain 4:2:0 8-bit stays NV12. Version bale.40 treats unspecified colour tags on SDR video 1280x720 and larger as BT.709 for that route. Version bale.39 adds the SDR downscale route (BT.709 SDR larger than the output target goes through bale_gpu's scale-only pass to P010). Version bale.38 adds the debug-only bale_tonemap_output_width/height keys (display-sized tone-map output through bale_gpu's area downscale). Version bale.37 marks the tone-map stage's output media type as tone-mapped for Bale's output guard. Version bale.36 makes the tone-map stage output P010 (10-bit) when bale_gpu reports P010 support, NV12 otherwise. Version bale.35 adds the debug-only bale_tonemap_format key (NV12, P010 or BGRA8 output with mask bit 8). Version bale.34 adds mask bit 8 (the fork stage without bale_gpu, debug only). Version bale.33 adds a debug-only bale_tonemap_output bitmask (decoder-style output copies, no output colour attributes, no per-frame Flush). Version bale.32 adds output-pool counters and a device-removed log line. Version bale.31 adds teardown diagnostics (d3d11 provider created/destroyed, tone map destroyed, source closed). Version bale.30 adds an opt-in sessionless fast seek (bale_fast_seek_without_session) and a NativeBuffer capacity fix. Version bale.29 makes HLG (BT.2100) eligible for the tone-map stage. ## androidx Media3 (CEA-608 closed captions)

`bale_gpu.dll`'s closed caption decoder (`native/bale-gpu/src/subs/cc`) ports parts of
[androidx Media3](https://github.com/androidx/media) (commit `9c1739438bf4ee07cecaed0302b632c5f5f55990`):
`Cea608Decoder.java` (character tables, validity and parity checks, repeated control codes, service
tracking, pop-on alignment), `CeaUtil.java` and `UserDataReader.java` (the A/53 SEI and user data walk)
and `ReorderingBufferQueue.java` (the PTS-ordered queue), rewritten in Rust and changed for Bale.
Media3 is licensed under the Apache License 2.0, whose text is packaged as `Licenses/FFmpegInteropX.txt`;
it ships no NOTICE file. `native/bale-gpu/NOTICE` records the files and changes.

Copyright (C) 2016, 2017, 2018 and 2024 The Android Open Source Project

The CEA-608 behaviour otherwise follows the decoder rules of the former 47 CFR 15.119 (a US federal
regulation, public domain). FFmpeg's `ccaption_dec.c` and AetherEngine (LGPL) were read for behaviour only;
no code was copied from them.
